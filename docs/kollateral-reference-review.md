# Kollateral reference review

Reviewed 12 October 2026 at commit `34e26116f4600adc9b700d55afda5ce52529b10e`. This is a source review, not a claim that its deployed integrations were tested. No source has been imported; no explicit compatible license was found in the checked repository.

| Feature in their code | In simple words | Tradepost adaptation |
|---|---|---|
| [Archive importer](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/scripts/import-archive.ts) | Save the original post, time, link and a text fingerprint; skip duplicates. | Preserve versioned observations of extension-detected calls, including capture source and first/last seen. Registered calls already save original text; detected posts currently retain a hash and classification, not full text history. |
| [Timeline scraper](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/scripts/scrape-x.ts) | Resolve an account ID, read pages of posts, skip reposts, slow down requests. | Prefer visible extension observations and supported X API access for authorized accounts. Their scraper requires an X session cookie and hard-coded internal GraphQL query IDs; it is fragile and not part of our implementation. |

An unavailable embed does not prove deletion, motive or a failed call. Checks are not yet persisted. |
| [Deletion recheck script](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/scripts/recheck-deletions.ts) | Mark IDs supplied by a person who checked them. | Add durable check history and a resumable background queue; this script itself is not an unattended X deletion monitor. |
| [Creator dossier](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/lib/dossier.ts) | A report card with itcall history, results and missing-post statistics. Deleted calls stay in the calculation. | Keep archived calls in evaluation; add evidence timeline and filters. Call results remain hypothetical, separate from actual wallet fills and returns. |
| [Creator analytics](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/lib/insights.ts) | Best/worst calls, favorite tokens, results by token, frequency and directional bias. | Add only after enough evaluated calls exist; show coverage and sample size. Avoid an average that silently hides unresolved calls. |
| [Scoring](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/lib/score.ts) | Calculate what a hypothetical $1,000 following a call would have made; compare with ETH. | Existing integer-based entry/expiry evaluation; label hypothetical results. Future benchmark must use matching timestamps and explicit fees/slippage assumptions. |
| [Historical prices and wallet swaps](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/lib/subgraph.ts) | Check prices at call time and whether the caller's wallet traded the other way. | Nansen observations with asset, network, time, transaction and coverage; Envio for our Monad fills. | [Inference verification](https://github.com/RomarioKavin1/kollateral/blob/34e26116f4600adc9b700d55afda5ce52529b10e/app/lib/verify.ts) | Try to prove which service produced an AI answer. | Show extraction source; CRE produces settlement reports from fixed call terms and sourced prices. CRE is not a substitute for TEE inference attestation. Their verifier explicitly returns unavailable without a per-response signature. |
| Trading and creator discovery | Follow a call, inspect its creator, or take an opposing position. | Kuru spot and Perpl perps with explicit review and limits. Spot sell requires owned inventory; never silently create a short. |

## Delivery order

1. **Implemented in this branch:** profile-header record restored, ordinary feed posts remain untouched, call-only trade entry; registered-call archive timestamps and on-demand X public availability checks. Tests cover missing embeds and auth/rate/network failures. Real-X reload validation pending.
2. **Next:** append-only snapshots for extension-detected calls, text hashes, capture provenance, edits as separate versions, and a dashboard timeline. Keep author-ID verification separate from handle-only observations.
3. **Then:** persist availability observations with provider/reason/check time, repeated checks and history; background batching, backoff and resumable pagination. No public “deleted” badge from a single 404, private account, suspension or provider outage.
4. **Then:** best/worst calls, asset breakdown and performance curve from evaluated calls, showing open/unresolved sample coverage; transaction-linked Nansen consistency findings beside them.
5. **Demo:** profile → archived call → availability check → evidence timeline → approved Kuru/Perpl order → Envio-confirmed fill; CRE separately evaluates bonded call expiry.

Availability checks are read-only, scoped to stored registered calls and limited in-process to 10/minute per client and 60/minute globally per server instance. They do not update the archived post, verdict, stake or settlement terms. The limiter is not distributed. Full unattended monitoring needs durable storage and a supported lookup source; it is not shipped by this step.
