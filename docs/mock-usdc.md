# Mock USDC demo token

`contracts/src/MockUSDC.sol` implements Call My Bluff Mock USDC (`mUSDC`) with six decimals. It is original test infrastructure, not Circle USDC, and has no dollar backing or monetary value.

Deployment mints `10000000000` raw units (10,000 mUSDC) to the specified recipient. The app fixes that recipient to the current server-verified bound wallet. Other addresses may call `faucet()` once for `1000000000` raw units (1,000 mUSDC); the initial recipient is already marked claimed. The faucet is intentionally not Sybil resistant. There is no owner, privileged mint key or custody backend. Deployment and faucet minting revert outside Monad testnet 10143.

## Deployment handoff

1. Sign in on `/creator/stake` and choose **Prepare mock USDC deployment**. The server estimates gas for repository-generated bytecode and the bound recipient. Review the demo-token terms and continue to Privy; submit final approval yourself.
2. Verify the successful creation receipt, deployed runtime, six decimals, `mUSDC` symbol and initial wallet balance before configuring its address. No real mock deployment is claimed until those checks succeed.
3. Set server-only `STAKE_TOKEN_MODE=mock` and `MOCK_USDC_ADDRESS=<confirmed token>`. Set `CREATOR_STAKE_ADDRESS` empty to prepare a new stake contract using this token. The existing Circle-token stake contract cannot change its immutable token. Preserve its deployment record and any balances; never represent one contract's deposits as another's.
4. Deploy the new stake contract with minimum `500000000` and cooldown `604800`, verify its receipt/settings, and set its confirmed address. Update Envio's contract/start block, regenerate and typecheck. Preserve chain+contract namespaces for projections and historical evidence.
5. Review an exact 500-mUSDC allowance and deposit as separate transactions. Mock currency proves the testnet flow, not a real $500 commitment or profitable advice.

The app defaults to Circle test USDC until mock mode is explicitly configured. Mock mode validates token metadata and matching stake immutables and is available only on testnet. No automatic network/token substitution or signing occurs.

Foundry tests cover exact initial/faucet units, duplicate claims, wrong-chain deployment/minting and a complete bounded-approval → active stake → withdrawal request → cooldown → full refund using the mock token.
